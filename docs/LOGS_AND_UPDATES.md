# 日志导出与检查更新（0.1.35）

## 导出日志

设置页 → 运行与诊断 → 导出日志。

- “诊断日志（无需 Root）”：导出模块/Gboard/Android 版本、设备型号、配置同步、Hook 状态、权限状态、近期历史事件与当前应用能看到的 PixelBoardLS logcat。
- “包含 Gboard 模块日志（需要 Root）”：额外使用 su 读取同一 PixelBoardLS 标签的跨进程 logcat；需要在设备上授权。读取超时或拒绝后，仍保存上面的诊断报告，并注明日志读取失败。
- 通过系统文件保存界面选择位置，输出 UTF-8 TXT；不申请存储权限，不自动发送日志，不主动读取输入文字、剪贴板内容、账号或设备序列号。
- 事件历史保存在模块私有空间，最多 64K 字符，单条最多约 2K；只记录通过现有来源身份检查的 Gboard 运行事件，以及配置同步结果/错误。历史标注模块版本和 PID，保留重启前事件以便排查。
- logcat 仅取最近 1200 条范围内的 PixelBoardLS 标签，输出最多 128K 字符。它不是完整 LSPosed 框架日志；日志缓冲已清空、此前未启用诊断或从未触发的事件无法补回。Android 14 以下无法使用现有带发送者身份校验的 Gboard 状态回传，可选 Root logcat 辅助排查。

## 检查更新

设置页 → 关于 → 检查更新。仅用户点击时联网查询仓库 `/releases/latest`，忽略草稿/预发布版，不将 Actions 测试包当作正式更新。

- 按数字段比较版本，支持 v 前缀与不同段数；高于最新正式版的测试包会明确显示其版本更高，不推荐降级。
- 显示当前/最新正式版本和更新说明，点击“前往下载”或“查看发布页”才打开本仓库对应发布页。不自动下载或安装 APK。
- 使用 HTTPS、连接/读取超时和最大响应限制。网络失败、限流、无正式 Release、无效 JSON/版本号均显示失败，不伪装成“已是最新版”。失败时可手动打开发布页。

## 验证

CI 检查：版本数字比较、测试版高于正式版、草稿/预发布和无效响应拒绝、可信下载页构造、UTF-8 与响应上限、历史日志限额、导出入口打开系统 CreateDocument、设置页浅深色启动及全部既有回归。Debug/R8 APK 构建、入口/签名/许可检查沿用原流程。

仍需在设备上确认文件提供程序实际保存、Root 授权/拒绝、跨进程日志可见范围及实际网络访问。本轮仅 Actions 测试构建，不发布 Release。
